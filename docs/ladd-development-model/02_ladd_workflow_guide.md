# LADD：分层代理驱动开发模式指南

`分层代理驱动开发 (Layered Agent-Driven Development - LADD)` 是一种融合了 `BMAD-METHOD` 战略规划能力与 `claude-code-spec-workflow` 战术执行能力的新型开发模式。它尤其适用于游戏开发等需要深度创意与复杂工程结合的领域。

## 一、 核心理念：战略与战术分离

LADD 模式将开发过程分为两个独立的层次：

1.  **战略层 (BMAD-METHOD 驱动):**
    - **职责:** 负责 **“做什么”** 和 **“为什么这么做”**。
    - **任务:** 处理高层次、富有创意、需要多领域知识融合的规划任务，如核心玩法设计、世界观构建、美术风格定义、技术架构选型等。
    - **参与者:** 游戏总监 (用户)、主策划代理、主美术代理、技术总监代理等。

2.  **战术层 (claude-code-spec-workflow 驱动):**
    - **职责:** 负责 **“如何做”**。
    - **任务:** 接收来自战略层的、明确可执行的开发任务，并将其高效、高质量地转化为经过测试的代码。
    - **参与者:** 人类开发者 (监督者)、`claude-code-spec-workflow` 的自动化命令和执行代理。

这种分层模式模拟了真实游戏工作室的协作方式，实现了创意规划与工程实现的分离与高效衔接。

## 二、 LADD 游戏开发工作流程

以开发一个新的 **“宠物伙伴系统”** 为例，展示 LADD 的完整流程。

### 阶段一：战略与创意规划 (BMAD 代理协作层)

**目标:** 定义“宠物伙伴系统”是什么，它如何与现有游戏系统交互，以及它的外观和感觉。

**步骤 1: 概念提出与需求定义**
- **行动:** `游戏总监 (用户)` 向 `主策划代理` 提出初步想法。
- **产出:** `主策划代理` 与总监协作，生成一份详细的 **产品需求文档 (PRD)**，包含核心玩法、系统关联、用户故事和验收标准。

**步骤 2: 跨领域设计细化**
- **行动:** PRD 被分发给其他专业代理。
    - `主美术代理` 根据 PRD 设计宠物的美术风格、动画规格，并生成 **美术设计概念图**。
    - `技术总监代理` 分析 PRD，评估技术可行性，并定义 **高层技术架构** 和接口。
- **产出:** 一套包含产品、美术、技术三个维度的完整设计文档。

**步骤 3: 生成可执行的任务蓝图**
- **行动:** `游戏架构师代理` 阅读所有设计文档，将其分解为一系列独立的 **技术任务蓝图 (Tech Task Blueprint)**。
- **产出:** 一个清晰的任务列表，例如：
    1.  `[Feature] PetData`: 创建宠物的数据结构和存储方案。
    2.  `[Feature] PetFollowingAI`: 实现宠物跟随玩家的AI逻辑。
    3.  `[Feature] PetCombatSystem`: 实现宠物参与战斗的系统。
    4.  `[UI] PetStatusPanel`: 创建显示宠物状态的UI界面。

---

### 阶段二：结构化实现与执行 (CCSW 自动化执行层)

**目标:** 将任务蓝图中的每一项高效地转化为高质量、经过测试的代码。

**步骤 4: 初始化 `spec` 并生成微观任务**
- **行动:** `人类开发者` 选取任务蓝图中的一项（如 `PetFollowingAI`），并使用 `claude-code-spec-workflow` 初始化一个 `spec`。
- **命令:**
  ```bash
  /spec-create pet-following-ai "Implement the pet's follow and idle behavior based on the tech architecture doc..."
  ```
- **产出:** `claude-code-spec-workflow` 自动为该功能生成详细的需求、设计和 **原子化的编码任务列表 (Tasks.md)**。

**步骤 5: 自动化代码实现**
- **行动:** 开发者启动 `spec-orchestrate`，让 AI 自动完成编码和单元测试。
- **命令:**
  ```bash
  /spec-orchestrate pet-following-ai
  ```
- **过程:** `spec-task-executor` 和 `spec-test-generator` 等代理协同工作，开发者通过 Dashboard 监控进度。

**步骤 6: 资产集成与人工审核 (人机协作)**
- **行动:** 当 UI 代码实现后，系统会提示需要美术资源。
- **过程:** `人类开发者` 或 `技术美术` 介入，将阶段一设计的美术资产（如图标、纹理）链接到代码中，并在本地预览效果。

**步骤 7: 验证与合并**
- **行动:** 所有相关 `spec` 完成后，进行最终的集成验证。
- **命令:**
  ```bash
  /spec-completion-review pet-system
  ```
- **产出:** 一份完整的报告，确认功能符合设计文档。确认无误后，开发者将功能分支合并到主干。

## 三、 融合模式的优势

1.  **两全其美:** 结合了 `BMAD` 的战略深度和 `CCSW` 的战术速度。
2.  **完美适应游戏开发:** 能够处理从模糊创意到具体代码的全过程。
3.  **清晰的责任边界:** 创意代理负责“想”，执行代理负责“做”，分工明确。
4.  **最佳的人机协作点:** 在需要创意、审美和决策的环节引入人类，在繁重的编码和测试环节发挥 AI 的优势。

LADD 模式为需要深度领域知识和复杂创意的软件项目提供了一个强大而可行的 AI 协作开发范式。
